# 面经详情渲染与投稿管理

## 1. 功能说明

本次改动解决了面经详情页富文本内容显示失控的问题，尤其是用户投稿中夹带 HTML/SVG 时导致的异常放大、白天主题下对比度差、内容区域样式混乱等问题。同时补齐了用户侧“我的投稿”管理能力，支持查看自己的投稿列表并编辑已有投稿，编辑后重新进入审核流程。

## 2. 涉及路由

| 方法 | 路径 | 说明 | 鉴权要求 |
| ---- | ---- | ---- | ---- |
| GET | `/api/v1/experiences/my/submissions` | 获取我的投稿列表 | 需登录 |
| GET | `/api/v1/experiences/my/submissions/{experience_id}` | 获取我的投稿详情 | 需登录 |
| PUT | `/api/v1/experiences/my/submissions/{experience_id}` | 更新我的投稿并重新提交审核 | 需登录 |

## 3. 核心实现逻辑

详情页和投稿预览页原先都是 `marked.parse()` 后直接交给 `v-html` 渲染，缺少 HTML 白名单清洗，导致复杂标签和外来样式直接进入页面。本次新增统一的 `renderExperienceContent()` 工具，对 Markdown 转换后的 HTML 再做一层白名单清洗，只保留常见阅读标签，并移除 `svg`、`style`、`iframe`、脚本类标签和危险属性。

详情页内容区的样式也重新整理为统一的阅读排版容器，对白天主题下的正文、引用块、代码块、表格做单独处理，避免出现“灰底深字不清楚”或“外来内容撑爆布局”的情况。对所有嵌入元素增加 `max-width` 约束，并禁止渲染清洗后的 `svg`。

用户投稿管理方面，新增“我的投稿”页面；投稿页复用为新建/编辑双模式。编辑模式下，前端先拉取当前用户自己的投稿详情，保存时调用新的用户侧更新接口；后端校验作者身份后更新正文、摘要、标签、匿名状态，并将状态重新置为 `pending`。

## 4. 数据库设计

本次不涉及数据库表结构变更，不需要新增 migration。
