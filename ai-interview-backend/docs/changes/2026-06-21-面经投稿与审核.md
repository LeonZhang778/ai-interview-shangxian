# 2026-06-21 面经投稿功能 + 管理审核 + Dashboard修复 + 审计日志

## 1. 功能说明

本次改动包含 4 个部分：

1. **面经投稿**：用户端新增面经投稿入口，登录用户可提交面经内容（标题、公司、岗位、正文、标签等），提交后面经进入 `pending` 待审核状态，审核通过后展示在面经广场。
2. **面经管理审核**：管理后台新增"面经管理"页面，管理员可查看所有面经（含待审核），支持按状态筛选、查看详情、通过/拒绝操作。
3. **Dashboard 数据修复**：管理后台数据概览页面的统计数据（注册用户数、面试总数等）不显示，原因是模板绑定字段错误。
4. **审计日志完善**：审计日志基础设施（模型、API、工具函数）已存在但从未被任何操作调用，导致日志页面始终为空。本次将审计日志集成到管理员登录、公告管理、用户管理等操作中。

## 3. 核心实现逻辑

### 面经投稿流程

请求进入 `experience.py` (client router) → Pydantic 模型校验参数 → 调用 `ExperienceService.submit_experience()` 创建 Experience 记录（status="pending"）→ 写入 experience_tags 表 → 返回投稿结果。

关键点：投稿的面经初始状态为 `pending`，区别于管理员直接创建的 `published` 状态。用户只能查看 `published` 状态的面经，管理员可以查看所有状态。

```python
experience = Experience(
    title=title, company=company, position=position,
    content=content, status="pending",  # 投稿默认待审核
    author_id=user_id, is_anonymous=is_anonymous,
)
```

### 管理审核流程

管理员通过 `PUT /backoffice/experiences/{id}/review?action=approve|reject` 操作，将面经状态从 `pending` 改为 `published` 或 `rejected`。操作同时记录审计日志。

```python
if action == "approve":
    experience.status = "published"
elif action == "reject":
    experience.status = "rejected"
```

### 路由顺序问题修复

`/submit` 和 `/my/submissions` 必须定义在 `/{experience_id}` 之前，否则 FastAPI 会把 `submit` 当作 experience_id 参数匹配到 `GET /{experience_id}`，导致返回 405 Method Not Allowed。

### 审计日志集成

`log_audit()` 函数之前缺少 `await db.commit()`，导致日志写入后不会持久化。修复后在各管理操作中调用：

```python
await log_audit(db, current_admin.id, "create", "announcement", announcement.id,
                f"创建公告: {title}")
```

### Dashboard 数据修复

模板中使用了 `{{ s.value }}`，但 `statCards` 数组中的对象只有 `key` 属性（如 `"user_count"`），没有 `value`。实际数据存储在 `stats` 响应式对象中。修复为 `{{ stats[s.key] }}`。

## 4. 数据库设计

本次无新增表或表结构变更。复用已有的 `experiences`、`experience_tags`、`user_collections`、`user_likes`、`experience_comments` 表。

`experiences.status` 字段已有 `draft` 和 `published` 两个值，本次新增 `pending`（待审核）和 `rejected`（已拒绝）两个状态值，无需 migration（VARCHAR 字段，应用层控制枚举值）。
