# 系统设置（System Settings）

> 日期：2026-06-20
> 涉及模块：后端 API、数据库、管理后台前端、用户端前端

---

## 1. 功能说明

新增系统设置功能，允许管理员在后台配置网站基础参数和功能开关，无需改代码或改配置文件。包含两部分：

**设置管理**：管理员可在后台页面修改网站名称、标语、Logo、SEO 信息、备案号、联系邮箱等参数，前端页面动态读取这些参数而非硬编码。

**功能开关**：三个布尔开关，修改后立即生效：
- **维护模式**：开启后所有客户端 API 返回 503，前台显示维护公告，后台管理不受影响
- **开放注册**：关闭后注册接口和发送验证码接口返回 403，新用户无法注册
- **游客模式**：关闭后游客登录接口返回 403，不允许未注册用户体验

## 2. 涉及路由

### 用户端 API（无需认证）

| 方法 | 路径 | 说明 | 鉴权 |
|------|------|------|------|
| GET | `/api/v1/config/site-info` | 获取公开站点配置 | 无 |

返回字段：`site_name, site_slogan, site_logo, seo_title, seo_description, icp_number, contact_email, register_enabled, guest_enabled`

### 管理后台 API（需管理员 JWT）

| 方法 | 路径 | 说明 | 鉴权 |
|------|------|------|------|
| GET | `/api/v1/backoffice/settings` | 获取所有设置 | 管理员 |
| PUT | `/api/v1/backoffice/settings` | 批量更新设置 | 管理员 |
| PUT | `/api/v1/backoffice/settings/{key}` | 更新单个设置 | 管理员 |

### 受功能开关影响的已有路由

| 路径 | 受哪个开关影响 | 关闭时行为 |
|------|---------------|-----------|
| `POST /api/v1/auth/register` | `register_enabled` | 返回 403 |
| `POST /api/v1/auth/send-verification-code`（code_type=registration） | `register_enabled` | 返回 403 |
| `POST /api/v1/auth/guest` | `guest_enabled` | 返回 403 |
| 所有 `/api/v1/*`（排除 config/health、config/site-info、backoffice） | `maintenance_mode` | 返回 503 |

## 3. 核心实现逻辑

### 3.1 设置读取服务（带 Redis 缓存）

所有功能开关的判断都通过 `setting_service.py` 读取，避免每次都查数据库。首次读取后缓存 60 秒，管理员更新设置时主动清缓存。

```python
# app/services/common/setting_service.py

CACHE_KEY = "system_settings"
CACHE_TTL = 60  # 秒

async def get_all_settings() -> dict:
    """读取所有设置，优先走 Redis 缓存"""
    try:
        cached = await redis_client.get(CACHE_KEY)
        if cached:
            return json.loads(cached)
    except Exception:
        pass

    SessionLocal = get_session_local()
    async with SessionLocal() as db:
        result = await db.execute(select(SystemSetting))
        settings = result.scalars().all()
        data = {s.key: s.value for s in settings}

    try:
        await redis_client.set_with_ttl(CACHE_KEY, json.dumps(data), CACHE_TTL)
    except Exception:
        pass
    return data

async def get_setting_bool(key: str, default: bool = True) -> bool:
    """读取布尔类型的设置值"""
    val = await get_setting(key, str(default).lower())
    return str(val).lower() in ("true", "1", "yes")

async def invalidate_settings_cache():
    """管理员更新设置后清缓存，下次读取会从数据库重新加载"""
    try:
        await redis_client.delete(CACHE_KEY)
    except Exception:
        pass
```

### 3.2 维护模式 + 功能开关中间件

在 `route.py` 的 `create_app()` 中注册 HTTP 中间件，所有客户端 API 请求先经过这里。中间件在 endpoint 的参数校验之前执行，所以即使请求体格式不对也能拦截。

```python
# app/route/route.py — create_app() 内

@app.middleware("http")
async def feature_toggle_middleware(request: Request, call_next):
    path = request.url.path
    # 仅拦截客户端 API，放行后台、健康检查、站点配置、文档、静态文件
    if (
        path.startswith("/api/v1/")
        and not path.startswith("/api/v1/backoffice")
        and not path.startswith("/api/v1/config/health")
        and not path.startswith("/api/v1/config/site-info")
        and not path.startswith("/api/v1/config/release")
        and not path.startswith("/client/")
        and not path.startswith("/backoffice/")
        and not path.startswith("/api-docs/")
        and not path.startswith("/uploads/")
    ):
        try:
            # 维护模式：拦截所有客户端 API
            if await get_setting_bool("maintenance_mode", False):
                return ApiResponse.failed(
                    message="系统维护中，请稍后再试",
                    body_code=503,
                    http_code=status.HTTP_503_SERVICE_UNAVAILABLE
                )
            # 注册开关：拦截注册相关接口
            if path in ("/api/v1/auth/register", "/api/v1/auth/send-verification-code"):
                if not await get_setting_bool("register_enabled", True):
                    return ApiResponse.failed(
                        message="注册功能已关闭", body_code=403,
                        http_code=status.HTTP_403_FORBIDDEN
                    )
            # 游客模式开关：拦截游客登录
            if path == "/api/v1/auth/guest":
                if not await get_setting_bool("guest_enabled", True):
                    return ApiResponse.failed(
                        message="游客模式已关闭", body_code=403,
                        http_code=status.HTTP_403_FORBIDDEN
                    )
        except Exception:
            pass  # settings 读取失败时放行，不阻塞正常请求
    return await call_next(request)
```

**设计决策**：把检查放在中间件而非仅在 endpoint 函数里，是因为中间件在 FastAPI 的请求体解析之前执行。如果只在 endpoint 里检查，当请求体缺少必填字段时，Pydantic 校验会先于功能开关检查返回 400，导致用户看到的是"字段缺失"而非"功能已关闭"。

### 3.3 站点配置公开接口

```python
# app/api/client/v1/config.py

@router.get("/site-info")
async def get_site_info():
    """无需认证，返回公开的站点配置字段"""
    from app.db.session import get_session_local
    SessionLocal = get_session_local()
    async with SessionLocal() as db:
        result = await db.execute(select(SystemSetting))
        settings = result.scalars().all()
        data = {s.key: s.value for s in settings}

    public_keys = [
        "site_name", "site_slogan", "site_logo",
        "seo_title", "seo_description",
        "icp_number", "contact_email",
        "register_enabled", "guest_enabled",
    ]
    site_info = {k: data.get(k, "") for k in public_keys}

    # 布尔字段转为实际 bool（数据库存的是字符串 "true"/"false"）
    for bool_key in ("register_enabled", "guest_enabled"):
        val = site_info.get(bool_key, "true")
        site_info[bool_key] = str(val).lower() in ("true", "1", "yes")

    return ApiResponse.success(data=site_info)
```

### 3.4 后台设置管理接口

```python
# app/api/backoffice/v1/setting.py

class SettingsBatchUpdate(BaseModel):
    settings: List[SettingItem]  # SettingItem = {key: str, value: Optional[str]}

@router.put("")
async def batch_update_settings(body: SettingsBatchUpdate, ...):
    """批量更新：遍历 body.settings，逐个查找并更新"""
    for item in body.settings:
        result = await db.execute(
            select(SystemSetting).where(SystemSetting.key == item.key)
        )
        setting = result.scalar_one_or_none()
        if setting:
            setting.value = item.value       # 已有则更新
        else:
            db.add(SystemSetting(key=item.key, value=item.value))  # 没有则新建
    await db.commit()
    await invalidate_settings_cache()  # 清缓存，立即生效
```

### 3.5 设置缓存失效时机

管理员通过后台 API 更新设置时，`setting.py` 的两个 PUT 接口都会在 `db.commit()` 后调用 `invalidate_settings_cache()` 删除 Redis 中的 `system_settings` key。下次客户端请求到来时，`get_all_settings()` 会从数据库重新加载并写入新缓存。

## 4. 数据库设计

### 新增表：`system_settings`

| 字段 | 类型 | 可空 | 默认值 | 说明 |
|------|------|------|--------|------|
| id | SERIAL | NOT NULL | 自增主键 | |
| key | VARCHAR(100) | NOT NULL | — | 设置项键名，UNIQUE |
| value | TEXT | NULL | — | 设置项值（布尔值也存为字符串 "true"/"false"） |
| description | VARCHAR(255) | NULL | — | 设置项中文说明 |
| created_at | TIMESTAMP WITH TIME ZONE | NOT NULL | now() | 继承自 BaseModel |
| updated_at | TIMESTAMP WITH TIME ZONE | NOT NULL | now() | 继承自 BaseModel，自动更新 |

**索引**：
- `system_settings_pkey` — 主键 (id)
- `system_settings_key_key` — UNIQUE 约束 (key)
- `ix_system_settings_key` — B-tree 索引 (key)

**建表方式**：因 alembic autogenerate 在旧容器中生成了空迁移，最终通过 `psql` 直接执行 DDL 创建。Migration 文件需后续清理。
