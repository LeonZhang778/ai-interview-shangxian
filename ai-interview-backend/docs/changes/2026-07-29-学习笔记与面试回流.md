# 学习笔记与面试回流

> 日期：2026-07-29
> 类型：新功能（P0）
> 状态：已完成

---

## 1. 功能说明

新增「学习笔记」模块，让用户沉淀面试知识、记录薄弱点、复盘每一次成长。核心能力是 **AI 面试结果自动回流**——用户完成一场 AI 模拟面试后，系统自动将面试报告（含总体评价、亮点、薄弱点、改进建议、逐题记录与错题标记）组装为一份 Markdown 格式的复盘笔记草稿，用户可在草稿基础上编辑完善后发布。

**解决的问题：**
- 面试做完即走，知识没有沉淀，薄弱点容易被遗忘
- 手动整理笔记门槛高，用户不知道该记什么
- 缺少私密学习空间，用户不愿意一开始就公开面经

**设计理念（低门槛 UGC 闭环）：**
- 私密优先：笔记默认 `private`，用户先写给自己，再决定是否公开
- 面试回流自动生成草稿，降低记录门槛
- 五种笔记类型覆盖不同学习场景：笔记 / 复盘 / 错题 / 面经 / 资料
- 公开广场精选优质笔记，形成社区知识库

## 2. 涉及路由

| 方法 | 路径 | 说明 | 鉴权要求 |
|------|------|------|---------|
| GET | `/api/v1/learning-notes/my` | 我的笔记列表（支持类型/状态/关键词筛选） | 需登录 |
| GET | `/api/v1/learning-notes/public` | 公开笔记广场（支持排序/搜索） | 不需要 |
| GET | `/api/v1/learning-notes/{id}` | 笔记详情（非作者仅可查看已发布的公开笔记） | 可选 |

| PUT | `/api/v1/learning-notes/{id}` | 更新笔记（仅作者） | 需登录 |
| DELETE | `/api/v1/learning-notes/{id}` | 删除笔记（仅作者） | 需登录 |
| POST | `/api/v1/learning-notes/from-interview` | 从 AI 面试结果生成学习笔记草稿 | 需登录 |
| GET | `/api/v1/learning-notes/stats` | 获取用户笔记统计（按类型计数） | 需登录 |

## 3. 核心实现逻辑

### 3.1 面试结果回流（核心方法 `generate_from_interview`）

请求链路：
- `POST /learning-notes/from-interview` → `learning_note_service.generate_from_interview()` → 加载面试记录 → 校验面试状态为 `completed` → 查重（同一面试不重复生成） → 解析面试报告 JSON → 组装 Markdown 草稿 → 保存为 `source="interview"` 的草稿笔记

自动组装的草稿内容结构：
```markdown
# {岗位} 面试复盘

> 得分：**8.5/10**
> 难度：medium | 题数：5

## 总体评价
{report.summary}

## 亮点
- {strengths[0]}
- {strengths[1]}

## 薄弱点
- {weaknesses[0]}

## 改进建议
- {suggestions[0]}

## 逐题记录
### 第1题 [✅ 通过 | 得分 8.0/10]
**我的回答：**
{answer}

**AI 评语：**
{feedback}

### 第2题 [❌ 错题 | 得分 4.5/10]
**我的回答：**
{answer}

**AI 评语：**
{feedback}
```

关键设计：
- **错题标记**：得分 < 6.0 自动标记为 `❌ 错题`，否则标记为 `✅ 通过`
- **查重机制**：同一 `interview_id` + `user_id` + `source="interview"` 的笔记已存在则直接返回已有笔记，不重复生成
- **错题类型自动标签**：若 `note_type="mistake"`，自动从 `report.weaknesses` 提取前 5 个作为 tags

### 3.2 面试完成自动回流

在 LangGraph 的 `save_results_node` 中，当面试完成（`is_finished=True`）时，在发送通知之后自动调用回流方法：

```python
if is_finished:
    # ... 发送面试完成通知 ...

    # 面试结果回流：自动生成学习笔记草稿（review 复盘类型）
    try:
        from app.services.client.learning_note_service import learning_note_service
        await learning_note_service.generate_from_interview(
            db=db,
            user_id=user_id,
            interview_id=interview_id,
            note_type="review",
            title=f"{state['target_position']} 面试复盘",
            visibility="private",
        )
    except Exception as e:
        logger.warning(f"自动生成学习笔记草稿失败: {e}")
```

失败不影响主流程，仅记录警告日志。

### 3.3 可见性控制

- `private`：仅作者可见
- `public` + `published`：进入公开广场
- 非作者访问时自动增加 `view_count`，仅限 `public` + `published` 的笔记

## 4. 数据库设计

新增 `learning_notes` 表：

| 字段 | 类型 | 是否可空 | 默认值 | 说明 |
|------|------|---------|--------|------|
| `id` | Integer | 否 | 自增 | 主键 |
| `user_id` | Integer (FK → users.id) | 否 | - | 作者 ID，级联删除 |
| `title` | String(200) | 否 | - | 标题 |
| `content` | Text | 否 | "" | Markdown 正文 |
| `note_type` | String(20) | 否 | "note" | 类型：note/review/mistake/experience/material |
| `visibility` | String(20) | 否 | "private" | 可见性：private/public |
| `status` | String(20) | 否 | "draft" | 状态：draft/published |
| `tags` | String(500) | 是 | NULL | 逗号分隔的标签 |
| `interview_id` | Integer (FK → interviews.id) | 是 | NULL | 关联面试记录，删除时置空 |
| `source` | String(20) | 否 | "manual" | 来源：manual/interview |
| `view_count` | Integer | 否 | 0 | 浏览量 |
| `like_count` | Integer | 否 | 0 | 点赞数 |
| `created_at` | TIMESTAMP | 否 | - | 创建时间 |
| `updated_at` | TIMESTAMP | 否 | - | 更新时间 |

索引：
- `ix_learning_notes_user_type`：(user_id, note_type) — 加速用户按类型筛选
- `ix_learning_notes_visibility`：(visibility, status) — 加速公开广场查询
- `interview_id` 单独索引 — 加速回流查重

迁移文件：`migrations/versions/e1a2b3c4d5e6_add_learning_notes.py`
