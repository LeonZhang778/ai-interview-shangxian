# 2026-06-20 运营与管理增强（Phase 3）

## 1. 功能说明

本次实现了三个后台管理功能，面向平台管理员：

- **数据分析报表**：Dashboard 增强，新增用户注册趋势、面试完成趋势折线图，面经点赞/收藏 Top 10 排行，活跃用户统计（DAU/WAU），平台总览数据（总用户、总面试、总面经、平均分等）。
- **用户反馈管理**：用户端右下角悬浮反馈按钮可提交 Bug/建议/其他反馈；后台可查看反馈列表、按状态/类型筛选、回复反馈并标记状态。
- **操作日志**：后台可查看管理员操作日志，支持按操作类型/对象/时间范围筛选，支持 CSV 导出。

## 3. 核心实现逻辑

### 数据分析报表

`analytics.py` 中各 endpoint 直接用 SQLAlchemy `select + func.count/avg` 聚合查询，按日期分组生成趋势数据。`experience-ranking` 用 `outerjoin` 连接 `user_likes`/`user_collections` 表统计排行。注意 `UserCollection` 无 `id` 列（复合主键），需用 `func.count(UserCollection.user_id)` 替代。

前端 Dashboard 用 `echarts` 渲染折线图，`onMounted` 中并行请求 5 个 API，`Promise.all` 加速加载。

### 用户反馈管理

客户端 API 不需要认证，直接写入 `feedbacks` 表。后台 API 支持按状态/类型筛选分页。回复时自动设置 `status=resolved` 和 `resolved_at`。

前端 BugReportBanner 改造为完整反馈表单，支持选择类型、填写内容和联系方式，通过 `URLSearchParams` 提交。

### 操作日志

`audit.py` 提供 `log_audit()` 工具函数，后台关键操作后调用即可记录。`audit_log.py` API 支持筛选和 CSV 导出（`StreamingResponse` + `csv.writer`）。

## 4. 数据库设计

### 新增表 `feedbacks`

| 字段 | 类型 | 说明 |
|------|------|------|
| id | SERIAL PK | 主键 |
| user_id | INTEGER FK(users.id) | 用户ID，可空（游客） |
| content | TEXT | 反馈内容 |
| feedback_type | VARCHAR(20) | bug/suggestion/other |
| contact | VARCHAR(100) | 联系方式 |
| page_url | VARCHAR(500) | 反馈时所在页面 |
| screenshot_url | VARCHAR(500) | 截图URL |
| status | VARCHAR(20) | pending/processing/resolved/ignored |
| admin_reply | TEXT | 管理员回复 |
| resolved_at | TIMESTAMPTZ | 解决时间 |
| created_at | TIMESTAMPTZ | 创建时间 |
| updated_at | TIMESTAMPTZ | 更新时间 |

### 新增表 `audit_logs`

| 字段 | 类型 | 说明 |
|------|------|------|
| id | SERIAL PK | 主键 |
| admin_id | INTEGER FK(admins.id) | 管理员ID |
| action | VARCHAR(50) | 操作类型 |
| target_type | VARCHAR(50) | 操作对象类型 |
| target_id | INTEGER | 对象ID |
| detail | TEXT | 操作详情 |
| ip_address | VARCHAR(45) | IP地址 |
| created_at | TIMESTAMPTZ | 创建时间 |
| updated_at | TIMESTAMPTZ | 更新时间 |
