# 2026-06-21 通知系统 + 面经模拟面试 + 面试历史分析

## 1. 功能说明

本次实现三个高优先级功能：

1. **消息通知系统**：站内通知，支持面试完成、面经审核通过/拒绝时自动发送通知。用户可在通知中心查看、标记已读、删除。导航栏显示铃铛图标和未读角标，每 60 秒轮询。
2. **面经 → AI 模拟面试**：用户在面经详情页可一键触发 AI 根据面经内容生成同类型面试题，选择题数后进入模拟面试。打通面经广场和 AI 面试两个核心场景。
3. **面试历史对比分析**：用户完成多次面试后，系统分析面试历史，展示分数趋势柱状图、维度分析条形图、最弱维度和进步率。

## 3. 核心实现逻辑

### 通知系统

通知采用数据库存储 + 前端轮询模式：

- `NotificationService` 提供 CRUD 操作（create, get_notifications, get_unread_count, mark_read, mark_all_read, delete）
- 通知触发点：`interview_service.py` 中面试完成时、`backoffice/experience.py` 中面经审核通过/拒绝时
- 前端 `App.vue` 每 60 秒调用 `GET /unread-count`，有未读时显示红色角标

```python
# 面试完成时触发通知
if is_finished:
    await notification_service.create_notification(
        db=db, user_id=user_id,
        title="面试已完成",
        content=f"你的「{interview.target_position}」面试已结束，得分 {overall} 分",
        notification_type="interview",
        related_id=interview.id, related_type="interview"
    )
```

### 面经模拟面试

核心改动是让 `Interview` 模型支持两种模式：基于简历的传统面试和基于面经的模拟面试：

- `resume_id` 改为 `nullable=True`，新增 `experience_id` 字段
- `AIService.generate_questions_from_experience()` 根据面经内容生成面试题
- `submit_answer` 和 `submit_answer_stream` 中，当 `experience_id` 存在时，用面经内容作为上下文替代简历

```python
# 获取上下文：简历或面经
if interview.resume_id:
    resume = await db.get(Resume, interview.resume_id)
    parsed_resume = json.loads(resume.parsed_content)
elif interview.experience_id:
    exp = await db.get(Experience, interview.experience_id)
    parsed_resume = {"summary": f"面经：{exp.title}", "skills": [exp.company, exp.position]}
```

### 面试历史分析

`GET /interviews/analysis` 接口分析用户所有已完成面试：

1. 查询所有 `status="completed"` 的面试记录
2. 从 `report` JSON 字段中提取各题评分，计算维度平均分
3. 计算进步率：前半段 vs 后半段平均分的变化比例

## 7. Bug 修复记录

部署后发现并修复了以下问题：

### Bug 1：面经模拟面试 500 错误

**现象**：`POST /api/v1/experiences/{id}/practice` 返回 500 Internal Server Error

**根因**：`ai_service.py` 未正确部署到容器中，`generate_questions_from_experience` 方法不存在。

**修复**：重新上传 `ai_service.py` 到容器并重启。

**验证**：修复后调用接口返回 200，成功创建面试记录。

### Bug 2：面经审核通知未发送

**现象**：管理员审核通过面经后，用户未收到通知。

**根因**：Experience 模型使用 `author_id` 字段存储投稿者 ID，但通知代码错误地使用了 `exp.user_id`，导致 `AttributeError: 'Experience' object has no attribute 'user_id'`。

**修复**：将 `exp.user_id` 改为 `exp.author_id`，并增加 `exp.author_id` 非空检查。

```python
# 修复前
if exp:
    await notification_service.create_notification(db=db, user_id=exp.user_id, ...)

# 修复后
if exp and exp.author_id:
    await notification_service.create_notification(db=db, user_id=exp.author_id, ...)
```

**验证**：修复后端到端测试通过——提交面经 → 管理员审核通过 → 用户收到通知（unread count = 1）。
