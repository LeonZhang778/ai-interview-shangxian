# 视频工具箱产品需求

## 1. 背景

`项目1` 已具备一套基于 FFmpeg 的桌面和 Web 媒体处理能力。当前项目需要把其中可复用的媒体功能变成网站工具箱，服务于已登录用户，同时复用当前项目的账号、任务、对象存储和审计体系。

## 2. 目标

- 提供统一的网站入口处理视频和音频文件。
- 首批支持视频转换、视频压缩、视频转 GIF、视频提取音频、音频转换。
- 第二阶段支持视频合并、添加水印。
- 采用异步任务，支持进度查询、失败重试、结果下载和自动清理。
- 不让用户接触服务器真实路径，不依赖 Electron。

## 3. 非目标

- 不迁移 Electron 窗口控制、机器码授权、桌面更新器。
- 不迁移原项目的账号中心、会员支付、广告和品牌页面。
- 第一阶段不开放任意 URL 下载、二维码传文件和移除水印。
- 不把原项目的 Express 服务直接嵌入 FastAPI。

## 4. 需求

- REQ-MEDIA-001：用户可上传受支持的视频或音频文件。
- REQ-MEDIA-002：用户可选择工具和受白名单约束的输出参数。
- REQ-MEDIA-003：服务端创建异步媒体任务并返回任务 ID。
- REQ-MEDIA-004：用户可查询任务状态和进度。
- REQ-MEDIA-005：完成后返回一次性或短时效下载地址。
- REQ-MEDIA-006：失败任务返回可理解的错误分类，不暴露 FFmpeg 原始命令和服务器路径。
- REQ-MEDIA-007：用户只能查看和下载自己的任务。
- REQ-MEDIA-008：超过大小、时长、并发和磁盘配额时拒绝任务。
- REQ-MEDIA-009：任务、文件和下载行为写入审计与指标。
- REQ-MEDIA-010：管理员可查询失败任务并重试或终止任务。

## 6. 成功指标

- P0 工具任务成功率不低于 95%。
- 正常任务创建接口 p95 小于 500ms，不含媒体处理耗时。
- 任务状态查询 p95 小于 300ms。
- 失败任务不泄露本地路径、命令行、凭据和内部堆栈。
- P0 工具至少覆盖 20 个真实样例文件格式。
