## 一、架构对比：当前项目 vs 项目1

| 维度 | 当前项目 (ai-interview-shangxian) | 项目1 (kunqiu-video-converter) | 结论 |
|------|------|------|:---:|
| **组件组织** | 单文件巨型组件（MediaTools.vue ~1250行） | 每工具独立视图（7个模块）+ 6个共享组件 | ❌ 当前差 |
| **路由** | 单个 `/media-tools`，靠 ref 切换 | 独立路由 `/video-convert`、`/video-merge` 等 | ❌ 当前差 |
| **状态管理** | 局部 ref（selectedFile/selectedFiles） | Pinia fileStore（按工具维度管理） | ❌ 当前差 |
| **UI组件库** | 自定义 CSS（CSS 变量体系） | Element Plus | — 风格不同 |
| **i18n** | 无 | vue-i18n 30+ 语言 | — 当前一致 |
| **类型** | JavaScript | TypeScript | — 风格不同 |
| **文件上传** | 选文件即上传到服务器 | 选文件加入本地列表，处理时再上传 | ❌ 当前差 |
| **视频预览** | 无（仅文本元数据） | 缩略图 + 点击播放 | ❌ 当前差 |
| **水印编辑器** | 纯表单，无预览 | 视频预览 + 拖动定位 + 时间轴 + 平铺/九宫格 | ❌ 当前差 |
| **合并工具** | 上移/下移按钮 + 文件名文本 | 缩略图 + 时长 + 大小 + 排序 + 播放 | ❌ 当前差 |
| **任务历史** | 文字列表，无缩略图 | 文件列表项 + 进度 + 状态 | ❌ 当前差 |
| **反馈机制** | errorMessage 单区域 | ElMessage toast + 字段级错误 | ❌ 当前差 |
| **图标** | emoji/字符（↗ ▤ ⌁ ♫ ✦ ⊕ ◇） | 内联 SVG | ❌ 当前差 |
| **高级参数** | 文本输入框（video_codec/audio_codec） | SettingsDialog 弹窗 + 预设选择 | ❌ 当前差 |
| **去水印功能** | 未实现 | 框选区域 + 模糊/填充 | ❌ 缺失 |

## 二、用户视角问题清单

以用户使用视角，按严重程度分组。

### P0 — 直接影响核心体验的问题

#### 1. 工具切换无独立路由，状态丢失
**问题：** 所有工具共用 `/media-tools`，页面刷新后回到默认 convert 工具，之前选的文件、设置的参数全部丢失。用户无法收藏/分享具体的工具页面（如"视频合并"），浏览器前进/后退键无法在工具间切换。

**影响：** 用户复制链接给同事，对方看到的是 convert 工具而不是 merge 工具。刷新后要重新选文件、设参数。

**文件：** `MediaTools.vue:366-386`（selectTool 定义）、`router/index.js:30`（单路由）

#### 2. 文件上传即提交，误选无撤销
**问题：** 点击文件选择后立即调用 `uploadMediaFile` 上传到服务器，上传统计中显示"已上传"但用户可能只是点错了。上传过程中无法取消，误选的文件也没有删除入口。

**影响：** 用户只是想看看文件信息，却被强制上传到服务器（消耗存储空间、带宽），且上传过程不可取消。

**文件：** `MediaTools.vue:448-458`（handleFileChange 直接调用 uploadFile）、`MediaTools.vue:480-498`（uploadFile 立即上传）

**项目1做法：** 文件先加入本地列表（`files` ref），用户点击"开始处理"才走完整流程。

#### 3. 水印无预览，盲调参数
**问题：** 水印参数全部是纯表单（类型radio、位置下拉、透明度数字、文字输入），用户无法看到水印在视频上的实际效果——位置选"右上角"但不知道具体坐标、透明度 0.5 看不出来什么效果、文字大小 36px 在 1080p 视频上有多大完全不知道。

**影响：** 用户只能"盲调"参数，提交任务后等待几分钟才能看到结果，不满意再重试，效率极低。

**文件：** `MediaTools.vue:394-406`（水印参数表单，纯表单无预览）

**项目1做法：** 视频预览 + 水印实时叠加 + 可拖动定位 + 时间轴，所见即所得。

#### 4. 合并视频无缩略图，选错风险高
**问题：** merge 的文件列表只显示文件名和大小，没有缩略图、没有格式/分辨率/时长展示。用户有 3 个相似命名的视频文件时，无法区分哪个是哪个。

**影响：** 用户可能选错文件顺序，合并后才发现不对，浪费时间重做。

**文件：** `MediaTools.vue:386-391`（merge-file-item 只显示文件名和大小）

**项目1做法：** 每个文件项有缩略图、时长、大小、格式 tag、分辨率，点击可播放预览。

#### 5. 表单参数切换工具后残留
**问题：** 从 compress 切换到 gif 后，`form.quality` 还保留着 compress 的值（"medium"），`form.resolution` 也保留着。从 trim 切换到 convert，`form.start_time` 和 `form.duration` 仍然存在。这些参数在目标工具中可能无意义或产生误导。

**影响：** 用户切换工具后忘记重置参数，用错误参数提交任务，结果不符合预期。

**文件：** `MediaTools.vue:394-410`（form reactive 共用）、`MediaTools.vue:432-442`（selectTool 只重置了部分字段，未重置 form）

### P1 — 严重影响体验但不影响核心功能

#### 6. 无视频预览和缩略图
**问题：** 上传完成后只显示文件名、大小、时长、分辨率（文本），没有任何视频缩略图或播放预览。用户无法确认选中的视频内容是否正确。

**影响：** 用户可能选中了错误的视频文件（比如面试录像选成了会议录像），直到下载结果才发现不对。

**文件：** `MediaTools.vue:448-478`（drop-zone 的 has-file 状态只显示 file icon + 文本信息）

**项目1做法：** 后端 FFprobe 可以提取 thumbnail（或前端用 `URL.createObjectURL` + `video` 元素截图），项目1 在 FileListItem 中展示缩略图。

#### 7. 任务提交无成功反馈
**问题：** `submitTask` 成功后直接 `loadTasks()` 并清空 `selectedFile`，没有任何 toast 提示"任务已提交"。用户可能以为操作没生效，反复提交。

**影响：** 用户重复提交任务，或困惑地等待几秒才发现任务出现在右侧列表。

**文件：** `MediaTools.vue:534-621`（submitTask 成功逻辑中无成功提示）

#### 8. 删除/重试/取消操作无反馈
**问题：** 删除任务、重试、取消、清空已完成等操作全部无 toast 反馈。只有 `errorMessage` 在出错时显示。用户不知道操作是否成功。

**影响：** 用户不确定操作是否生效，可能重复操作。

**文件：** `MediaTools.vue:652-725`（cancelTask、retryTask、deleteTask、deleteAllTasks 等均无成功反馈）

#### 9. 所有错误挤在一个区域
**问题：** 上传失败、参数校验失败、任务提交失败、删除失败全部显示在 `errorMessage` 同一个红框里，位于 workspace-card 中。历史卡片操作（删除失败）的错误也会显示在 workspace-card 里，位置不直观。

**影响：** 用户操作历史卡片时，错误提示出现在另一个区域，用户可能没看到。

**文件：** `MediaTools.vue:378`（errorMessage 单区域）、`MediaTools.vue:652-725`（各种操作共用 errorMessage）

#### 10. 高级参数门槛过高
**问题：** "视频编码器"和"音频编码器"直接给文本输入框，没有提示、没有预设下拉。普通用户不知道什么是 H.264、H.265、AAC、MP3，也不敢乱填。高级参数区域内容两极分化：有的预设下拉（采样率、声道），有的文本输入（codec），用户体验割裂。

**影响：** 普通用户看到文本框不敢填，高级用户又觉得预设不够用。

**文件：** `MediaTools.vue:258-302`（advanced-grid 内的 video_codec/audio_codec 文本输入框）

#### 11. 图标用 emoji/文字符号
**问题：** 工具图标用字符符号（↗ ▤ ⌁ ♫ ✦ ⊕ ◇），不同操作系统/浏览器渲染效果不同——Windows 和 macOS 的 emoji 风格差异很大，字符符号在不同字体下可能显示为方块/问号，或大小不一致。

**影响：** 品牌形象不一致，降低专业感。

**文件：** `MediaTools.vue:356-363`（tools 数组的 icon 字段）

### P2 — 体验优化

#### 12. 轮询无后台暂停
**问题：** `startPolling` 每 2 秒轮询所有活跃任务，但页面切换/隐藏后仍在轮询（onUnmounted 清理了 timer，但未添加 `document.visibilitychange` 监听，前台无法暂时暂停）。

**影响：** 用户切到其他标签页后，后台仍在轮询（浪费网络和计算资源），在移动端尤其消耗流量。

**文件：** `MediaTools.vue:635-649`（startPolling 纯 setInterval，无 visibilitychange 暂停）

#### 13. 合并文件无去重/类型检测
**问题：** 前端不检查 merge 文件是否重复添加、是否都是视频文件。用户可能把同一个文件添加两次，或混入音频文件。

**影响：** 合并任务失败（后端校验不过），或用户花时间等待后才发现文件重复/类型不对。

**文件：** `MediaTools.vue:448-458`（handleFileChange 对 merge 模式不做去重检测）

#### 14. 没有"我的文件"管理入口
**问题：** 后端有 `listMediaFiles` API 可以查询所有上传的文件，但前端没有入口。用户上传的文件无法管理/查看/删除，只能通过任务历史间接看到。

**影响：** 用户上传了多个文件后，无法管理这些文件，只能通过新建任务来"发现"已上传的文件。

**文件：** `MediaTools.vue:623-650`（loadTasks 只拉任务列表，无文件列表入口）

#### 15. 水印类型切换后参数不同步
**问题：** 水印类型字段分散：`watermarkType` 是独立 ref，`form.position`、`form.opacity` 是 form 的一部分，`watermarkText`、`watermarkFontSize`、`watermarkFontColor` 又是独立 ref。分散的状态管理让代码可维护性差，也容易导致参数不一致（比如从文字水印切回图片水印时，文字参数还在但不会提交）。

**影响：** 代码维护困难，参数不一致可能导致 bug。

**文件：** `MediaTools.vue:387-396`（watermark 相关状态分散在多个 ref 和 form 中）

#### 16. 无去水印功能
**问题：** 当前只有"添加水印"（watermark），没有"去水印"（remove-watermark）功能。蒸馏计划 M-06 提到后端已有去水印 API 设计（`RedactTaskCreate`），但前端未实现。

**影响：** 用户需要处理带水印的视频时，无法使用该平台。

**文件：** `MediaTools.vue:356-363`（tools 中无 watermark 去水印或 redact 工具）

#### 17. 标签嵌套（HTML 语法错误）
**问题：** 水印参数区域的 radio-group 使用了 `<label class="full-width">` 内嵌 `<div class="radio-group">` 内嵌 `<label class="radio-label">`，label 嵌套 label 是非法 HTML 结构，浏览器会解析错误，可能导致点击区域失效或表单关联错误。

**影响：** 点击 radio 选项的区域可能不灵敏，或屏幕阅读器无法正确识别。

**文件：** `MediaTools.vue:220-238`（radio-group 的 label 嵌套 label）

## 三、推荐重构方案（按项目1架构）

### 3.1 总体架构设计

按项目1的模块化思路，将单文件 MediaTools.vue 拆分为：

```
src/
├── views/
│   └── media/                      # 工具视图（独立路由，每个 .vue < 500 行）
│       ├── ConvertTool.vue          # 格式转换
│       ├── CompressTool.vue         # 视频压缩
│       ├── TrimTool.vue             # 视频截取
│       ├── ExtractAudioTool.vue     # 提取音频
│       ├── AudioConvertTool.vue     # 音频转换
│       ├── GifTool.vue              # 视频转 GIF
│       ├── MergeTool.vue            # 视频合并
│       ├── WatermarkTool.vue        # 添加水印
│       └── MediaTaskHistory.vue     # 任务历史列表（独立组件，可嵌入或独立路由）
├── components/
│   └── media/
│       ├── MediaFileDropZone.vue    # 拖拽上传区域（重用）
│       ├── MediaFilePreview.vue     # 文件缩略图 + 预览（重用）
│       ├── MediaParamPanel.vue      # 参数面板（基础/高级折叠）
│       ├── MediaWatermarkEditor.vue # 水印编辑器（预览 + 拖动 + 时间轴）
│       └── MediaTaskHistory.vue     # 任务历史列表（重用）
├── stores/
│   └── media.js                    # Pinia 状态管理（files, tasks, capabilities, polling）
└── api/
    └── mediaTool.js                 # 保持不动（API 封装已完善）
```

### 3.5 用户视角关键优化点

#### P2 增强

| 优化点 | 实现方式 |

| 任务结果预览 | 完成的视频任务可直接在浏览器播放（后端返回可播放 URL） |
| 批量重试 | "全部重试失败"按钮 |

## 五、风险与注意事项

1. **路由变更影响**：旧入口 `/media-tools` 改为重定向到 `/media-tools/convert`，侧边栏/导航中的链接需要同步更新。
2. **后端无改动**：此方案只涉及前端，后端 API 不变，`mediaTool.js` 不动。
3. **当前组件风格保持**：保持现有 CSS 变量体系（--bg-base、--accent-primary 等），不引入 Element Plus 或其他 UI 库。
4. **不引入 TypeScript**：保持当前 JavaScript 技术栈，不迁移到 TypeScript。
5. **不引入 i18n**：当前项目全站无 i18n，媒体工具保持一致。
6. **Pinia 维持**：当前项目已有 Pinia（auth store），新增 media store 不需要额外安装依赖。
7. **Toast 方案**：可引入 `sonner`（轻量，~0.5KB）或使用 Element Plus 的 ElMessage（但需引入 Element Plus），建议自定义简单的 toast 组件（参照现有 CSS 变量风格）。
