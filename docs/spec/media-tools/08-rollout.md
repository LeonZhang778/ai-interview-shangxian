# 媒体工具发布与回滚

## 1. 功能开关

- `media_tools_enabled`：默认 `false`，控制媒体工具入口和 API 创建任务。
- `media_tools_p0_enabled`：默认 `false`，控制转换、压缩、截取、音频提取和音频转换。
- `media_tools_p1_enabled`：默认 `false`，控制合并、GIF、水印和区域处理。
- `media_tools_batch_enabled`：默认 `false`，控制批量任务。

开关读取当前项目设置服务；关闭时 API 返回 `media_feature_disabled`，不影响历史查询和已完成结果下载。

## 2. 发布阶段

1. 开发环境：仅内部测试用户，验证 FFmpeg、S3、Celery 和数据库迁移。
2. 预发布：10 个内部账号，至少完成 100 个 P0 任务。
3. 小流量：1% 普通用户，观察 24 小时成功率、失败码和存储增长。
4. 扩大：10%、30%、100%，每阶段至少观察一个完整高峰周期。
5. P1 单独发布，不与 P0 同时切换。

成功门槛：P0 成功率 ≥97%、失败率不连续上升、队列等待 p95 <120 秒、无 P0 安全事件。

## 3. Kill switch

值班开发或管理员可关闭 `media_tools_enabled`。关闭后：停止新任务、保留状态查询、允许已完成结果下载、暂停批量入口。目标 MTTR 为 30 分钟内，公告说明不暴露用户文件信息。

## 4. 回滚

- 代码回滚：回退 API/worker 镜像到上一个已验证版本。
- 数据回滚：媒体表迁移采用向前兼容，不执行破坏性 down migration；必要时保留空表。
- 文件回滚：不删除用户原文件；仅清理本次版本创建的临时对象和失败结果。
- 配置回滚：关闭对应功能开关。

## 5. 数据迁移

上线前执行 Alembic migration，检查表、索引、外键和权限。上线后由清理任务回收过期对象；不得批量删除既有用户上传文件。

## 6. A/B

P0 不做视觉 A/B。后续可对“基础参数默认展开/折叠”做实验，主要指标为任务提交完成率，护栏指标为参数错误率和取消率；最小可检测差异为 5%，持续 14 天，出现错误率上升 20% 即停止。
